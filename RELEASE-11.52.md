# VK Leads 11.52 — непрерывные рабочие сеансы сборщика

Проблема: в фактическом расписании GitHub были паузы около восьми часов. Два прохода после такой паузы давали лишь несколько кандидатов с интервалом целиком внутри часа. Два обновления данных дополнительно не дошли до Pages из-за ошибки списка артефактов.

Изменения:
- Сервер выполняет повторные проходы с целевым интервалом 5 минут в ограниченном 50-минутном сеансе. Медленный проход заканчивается полностью, параллельные проходы не запускаются.
- Каждый успешный проход коммитит только проверенную ленту и checkpoint. Mini App читает актуальную JSON-ленту из этого же публичного GitHub-репозитория; Pages остаётся запасным источником. Выбирается более свежий валидный снимок. Публикация интерфейса больше не блокирует данные.
- После успешного сеанса создаётся ровно один workflow_dispatch следующего сеанса. Для этого используется штатный GITHUB_TOKEN с actions:write. Одновременно работает один сборщик, расписание служит восстановлением. Отмена задания не вызывает продолжение; Disable workflow останавливает цепочку. Сбой постоянного ключа не обходится.
- После push первый сеанс занимает 15 минут для проверки релиза. Следующие — 50 минут. На один проход действует тайм-аут 15 минут, на задание — 70 минут.
- Исправлено ошибочное восстановление границы по ширине браузерного диапазона 2000 вместо реального серверного диапазона 24000: наблюдения внутри проверенного окна больше не сбрасываются после паузы.
- Чтения groups.getById/wall.get повторяются при временной сетевой ошибке или VK 6/10, максимум два повтора с задержками. Ошибки доступа и авторизации не повторяются таким способом.

Ограничения: отсутствие ID/ответ delete НЕ является доказательством отсутствия сообщества в прошлом. Ранее скрытые или восстановленные сообщества возможны. Старые собственные фото и посты — признаки исключения, но отсутствие таких материалов не доказывает создание. Весь интервал наблюдения по-прежнему должен входить в выбранный час/1–3 часа/сегодня. После пропуска наблюдений точную историю невозможно восстановить задним числом. GitHub и VK не гарантируют бесперебойность или интервал 5 минут. Количество всех созданных групп не обещается.

Официальные источники:

- https://docs.github.com/en/actions/how-tos/troubleshoot-workflows — расписание может задерживаться.
- https://raw.githubusercontent.com/VKCOM/vk-api-schema/master/groups/objects.json — поля группы; регистрация не подменяется start_date события.
