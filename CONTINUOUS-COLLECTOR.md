# Постоянный сборщик — 11.36

Сбор работает в GitHub Actions и публикует community-feed.json вместе с сайтом. Компьютер и Mini App могут быть закрыты. Стандартный Linux runner публичного репозитория бесплатный. Расписание: 7, 22, 37, 52 минуты каждого часа. GitHub может задерживать или пропускать запуски; это не сервис с гарантированной задержкой. При отсутствии активности репозитория расписание может отключаться через 60 дней.

## Включение владельцем

1. Откройте https://github.com/German22Fed/vk-leads/settings/secrets/actions .
2. New repository secret: имя VK_SERVICE_TOKEN, значение — сервисный ключ вашего приложения VK, не защищённый ключ и не ключ сообщества. Не помещайте ключ в исходники или чат.
3. Actions → Collect VK communities → Run workflow → main.
4. Первый успешный запуск создаёт начальную границу автоматически. Никакие группы первого снимка не публикуются как новые. Для кандидата нужны минимум две успешные проверки отсутствия, затем появление полноценной группы.
5. При ошибке прав ключа к groups.getById / wall.get нужна разрешённая VK авторизация для этих методов. Вход пользователя в Mini App сам по себе не подключает сервер.

## Отбор и хранение

Начальная граница определяется существующим блочным поиском без ручного ID. Вперёд проверяются 2 000 номеров, диапазон продвигается автоматически. История хранится в collector-data/state.json; перезапуск не обнуляет базу. Группы с неполным ответом, удалённые, неподходящие названия, более 500 подписчиков, недоступной стеной или найденным постом до интервала появления не публикуются. Проверяется начало и конец стены. Удаление старых постов может скрыть возраст: реальное время регистрации по-прежнему неизвестно.

Подходящие кандидаты перепроверяются (до 40 за цикл). В публичную ленту попадают только проверенные в последний час записи. ID является уникальным ключом; обновление карточки не создаёт дубль и сохраняет локальный статус обработки. Повторные опросы не отправляют сообщений. Лента хранит до 500 карточек за 7 дней. При перегрузке возможны пропуски; полное покрытие VK не гарантируется. Данные старше часа скрываются в основной ленте, сохранённые карточки остаются в личных разделах.

При сбое цикл не перезаписывает checkpoint. Неверные ответы не засчитываются как отсутствие ID. Публичная база содержит только открытые данные сообществ и наблюдения; токен доступен лишь шагу сбора из GitHub Secrets. Публичность базы и истории Git отражена в политике внутри приложения. Для удаления опубликованных данных требуется отдельное обращение к владельцу репозитория; удаление локальной истории не удаляет Git.

## Проверка

node --test --test-isolation=none tests/*.test.mjs

Тесты используют моделируемый VK API: начальная база, новые ID, старые публикации, delete, нерелевантные названия, недоступная стена, повторный запуск, сбой, устаревшая лента и интервалы. Это не подтверждение настоящего подключения. Живой запуск проверяется по успешному workflow и обновлению community-feed.json после добавления ключа владельцем.

Источники ограничений хостинга: https://docs.github.com/en/billing/concepts/product-billing/github-actions и https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule .
