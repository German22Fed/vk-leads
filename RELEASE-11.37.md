# 11.37 — понятная реакция поиска и ошибки сборщика

Обнаружено: верхняя кнопка вызывала click() на второй кнопке, которая могла быть disabled во время фонового запроса. При повторном обновлении неизменной пустой ленты не было заметного результата. Последний проверенный серверный запуск 41113164362 завершился на Collect and verify: VK_SERVICE_TOKEN отсутствует. Это отдельная причина отсутствия настоящих групп.

Исправления:
- Прямой общий обработчик поиска, без click() на disabled-кнопке. Одновременные запросы объединяются, последующий поиск снова обращается к ленте.
- Индикатор загрузки и результат рядом с верхней кнопкой; отдельные состояния для отсутствия ключа, ошибки сети, некорректного ответа, устаревшей и пустой ленты.
- Счётчик учитывает выбранный период и фильтры. Периоды применяются без автопрокрутки.
- Ссылки на добавление секрета и журнал запуска в панели.
- CLI сохраняет безопасный код ошибки в feed.collector, оставляя предыдущие карточки, время успешного сбора и checkpoint. Workflow публикует диагностику даже при ошибке и завершает запуск со статусом failure, а не success.

Проверки: 107 тестов passed; браузерный локальный стенд с вымышленными карточками — отсутствие ключа, повторная верхняя кнопка, час, 1–3 часа. Тестовый стенд и данные не публикуются. Реальный сбор требует VK_SERVICE_TOKEN с доступом к нужным методам. Кнопка сайта загружает опубликованную ленту; она не запускает приватный GitHub workflow от имени посетителя и не восстанавливает отсутствующую историю.
