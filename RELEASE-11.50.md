# VK Leads 11.50 — производительность

## Что изменено
- 36 карточек на страницу; вся подборка доступна через «Назад» / «Следующие 36». Счётчики показывают общее число результатов. «Отметить показанные» относится к текущей странице.
- Повторный снимок не пересоздаёт неизменившиеся карточки. Убран дублирующий минутный таймер на GitHub Pages.
- Один Intl.DateTimeFormat вместо создания форматтера для каждой даты каждой карточки.
- Результаты проверки тематики и порноконтента кешируются на объекте с инвалидированием при изменении полей. Счётчики периодов вычисляются по одному разу на период без сортировки.
- Ввод поисковой строки объединяется в пересчёт через 140 мс после ввода.
- Вместо сохранения общей ленты на каждом обновлении сохраняются личные статусы, отметки просмотра, архив выбранных/обработанных карточек и ручной импорт. Статусы мигрируют из прежней базы до её уменьшения; сохранённые и обработанные сообщества остаются доступны.
- Устаревшие необработанные карточки сборщика больше не накапливаются в оперативной и локальной базе. Повторно найденный ID получает прежний личный статус.
- Охват сервера: 24 000 ID вместо 18 000 за проход. Проверка существования, старых постов и взрослого контента сохранена. Частота API не увеличена.

## Проверка
На одном реальном снимке из 695 сообществ (942 408 символов JSON): 10 расчётов фильтров/счётчиков до оптимизации — 12 641 мс, после — 747 мс, включая холодный старт. Отрисовка ограничена 36 карточками вместо 695; все 20 страниц доступны. Это замер вычислений Node на текущем компьютере, а не гарантия времени на каждом телефоне.
Автотесты дополнены проверками полного обхода страниц, миграции личных статусов, удаления только перезагружаемых снимков, сохранения истории после повторного появления ID и инвалидирования кеша фильтра.

## Ограничения
Рост ID остаётся оценкой новизны, не точной датой регистрации. Расписание GitHub может задерживаться. Нельзя гарантировать отсутствие всех ошибок на всех клиентах VK; текущая проверка охватывает тесты, публичный сайт и серверный запуск.
